# Задание 1 
## Уровень 1. Проектирование
Для выделения микрофронтендов из монолитного приложения был выбран фреймворк Webpack Module Federation. 
Он позволяет:
1. Подгрузить общие зависимости
2. Осуществить lazy-загрузку компонентов
3. С ним была более широкая экспертиза после выполнения лабораторной работы.

Дополнительно стоит отметить то, что изначально использовался только React, 
поэтому преимущество SPA(независимость от фреймворков) не требуется

## Уровень 2. Планирование изменений
С учтем совокупностей стратегий "Вертикальная нарезка" и "Изоляция" было принято решение разделить монолитное приложение
на 4 микрофронтенда:
1. design-system - библиотека общих компонентов и стилей(попапы, контент, футер, и тд). Эта библиотека позволит в
   будущем создавать новые страницы и компоненты, не заботясь о стилях и общих компонентах.
2. auth - микрофронтенд для авторизации и регистрации пользователей с возможностью использовать api. В будущем api будет
   выделен в отдельный микросервис.
3. profile - микрофронтенд для работы с профилем пользователя. Имеет свой api, который в будущем будет выделен в отдельный микросервис.
4. places - микрофронтенд для работы с карточкам мест и лайками. Имеет свой api, который в будущем будет выделен в отдельный микросервис.

host - не используется вместо него, используется App.js из бывшего монолита. Его ответственность теперь заключается только в подгрузке микрофронтендов 
и общем роутинге

Таким образом каждый микрофронтенд, в том числе и desing-system, становится независим и может разрабатываться и деплоиться отдельной команды.
